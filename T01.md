# T01 — Siapkan fondasi proyek dan arsitektur berlapis

Status: `done` (3 November 2026).

## Hasil

- Workspace pnpm berisi `apps/web`, `apps/server`, dan `packages/contracts`. Folder modul tambahan dibuat saat diperlukan, sesuai planning bagian 4.6.
- React, Vite, Fastify, TypeScript, kontrak health, validasi konfigurasi, composition root, dan aturan dependensi tersedia. Versi langsung dan runtime dipatok; lockfile disertakan.
- Jalur health: controller memanggil application, lalu response diperiksa terhadap kontrak bersama.
- Host dan port wajib dibaca dari `.env`. Logger menyaring field kredensial yang dikenali dan header otorisasi/cookie.

## Bukti verifikasi

- `pnpm install --frozen-lockfile`: berhasil dengan pnpm 12.9.1 dan Node 24.19.0.
- `pnpm build`, `pnpm typecheck`, `pnpm architecture`: lulus.
- `pnpm test`: 3 tes lulus, mencakup health, konfigurasi wajib, dan redaksi log.
- File probe sementara yang mengimpor infrastructure dari domain ditolak oleh `pnpm architecture` dengan `domain-is-pure`; file probe dihapus setelah pengujian.
- `pnpm dev`, lalu HTTP GET: backend `127.0.0.1:3000/health` dan proxy `127.0.0.1:5173/health` masing-masing `200 {"status":"ok"}`; halaman `127.0.0.1:5173/` menghasilkan HTTP 200 dan memuat judul aplikasi.

## Catatan pelaksanaan

- Root saat ini dipakai karena sudah berisi planning dan visual; tidak ada folder aplikasi yang bertabrakan. Port 3000 dan 5173 bebas saat diperiksa. Port Hermes 8642 tidak diubah.
- `pnpm install` awal menolak skrip build esbuild. Izin skrip esbuild dicatat di `pnpm-workspace.yaml`, lalu instalasi frozen berhasil.
- `Invoke-WebRequest` pada PowerShell lokal gagal dengan `NullReferenceException`; smoke test diulang menggunakan `fetch` bawaan Node.
- Redaksi log mencakup nama field dan header yang dikonfigurasi. Secret baru harus ditambahkan ke kebijakan redaksi dan diuji saat integrasi terkait dibuat.
