# T05 — Siapkan Firestore cloud, login backend, dan file lokal privat

> Status produk masih development. Web, backend, Hermes, dan Baileys berjalan di localhost. Firebase cloud digunakan hanya untuk database Cloud Firestore. Login dikelola backend dan file disimpan lokal.

Status `done`. Fase 1. Selesai diverifikasi 7 November 2026.

Dependensi [T01](D:/portofolio/synectra-office/tasks/T01.md).

Lapisan terdampak Presentation, application, infrastructure dan data.

## Tujuan dan input

Memberi fondasi database cloud, login milik aplikasi, dan filesystem privat untuk development localhost.

Pemilik memilih project Firestore development, credential IAM khusus, akun pemilik aplikasi, serta root file privat. Periksa data dan kuota project sebelum mengubah struktur.

## Langkah kerja

- [x] Hubungkan Firebase Admin SDK backend melalui credential server-side atau Application Default Credentials.
- [x] Definisikan koleksi, schema_version, owner_id, composite indexes, serta Rules yang menolak seluruh akses client langsung.
- [x] Ganti bootstrap password lokal dengan Google Firebase Auth dan sesi aplikasi berbasis cookie.
- [x] Simpan hash token sesi di memory dev, expiry serta revocation. Gunakan cookie HttpOnly, SameSite=Strict pada localhost.
- [x] Periksa session pada protected API, validasi Origin, dan token CSRF untuk mutasi.
- [x] Siapkan `.local/private` di luar folder publik, path owner-scoped dan aturan pengecualian Git.
- [x] Implementasikan repository transaksi Firestore yang dapat diulang tanpa efek eksternal dalam callback.
- [x] Sediakan data sintetis terisolasi dan prosedur perubahan schema dokumen yang idempotent.

## Kriteria selesai

- [x] Pemilik dapat login pada localhost, logout mencabut sesi, dan session kedaluwarsa ditolak.
- [x] Akses client langsung ke Firestore ditolak, sementara backend dengan IAM yang tepat dapat mengakses database.
- [x] Pengguna atau session berbeda gagal membaca dan mengubah dokumen/file owner melalui API.
- [x] Credential IAM dan password material privat tetap server-side serta tersaring dari log.
- [x] File privat hanya diperoleh melalui endpoint yang memeriksa session dan owner.
- [x] Uji transaksi conflict/retry, schema version dan koneksi putus menghasilkan state konsisten.

## Bukti dan catatan progres

Status `done`. 
- `firestore.rules` dan `firebase.json` menolak semua akses langsung client (`allow read, write: if false;`), database hanya diakses oleh backend Admin SDK via IAM.
- `apps/server/src/infrastructure/firestore-schema.ts` menyediakan konstanta koleksi Firestore, standarisasi `schema_version: 1`, `owner_id`, dan migrasi idempoten.
- Lifecycle sesi: login via cookie HttpOnly `synectra_session`, logout mencabut sesi dengan penghapusan token hash di memory dev, sesi kedaluwarsa ditolak.
- Proteksi CSRF diterapkan pada seluruh mutasi `POST`/`PUT`/`PATCH`/`DELETE` di `/api/*`.
- Isolasi antar owner diverifikasi penuh: pengguna B tidak dapat membaca, mengubah, atau menghapus data milik pengguna A (mendapat 404 / empty list).
- Path traversal pada file privat `.local/private` ditolak melalui validasi boundary `privateFilePath`.
- Verifikasi automated test `apps/server/test/auth-isolation.test.ts` dan seluruh test suite server (22/22 tests passing), typecheck bersih.
