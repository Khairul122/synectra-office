## Bukti dan catatan progres

### 1. Sajian Frontend Statis & SPA Fallback (`apps/server/src/bootstrap/app.ts`)
- Backend Fastify menyajikan file produksi frontend dari `apps/web/dist` melalui handler `setNotFoundHandler`.
- Dilengkapi proteksi path traversal ketat: menolak segment `..` dan encoding `%2e` dengan HTTP 400 Bad Request.
- Memeriksa ekstensi file statis: request file berekstensi yang tidak ada di disk mengembalikan HTTP 404 JSON (bukan HTML) untuk mencegah parsing error di browser.
- SPA fallback menyajikan `index.html` untuk rute navigasi aplikasi non-API (mengecualikan prefix `/api`, `/health`, `/auth`, `/whatsapp`).

### 2. Panel Health Layanan & Panduan Recovery (`apps/web` & `packages/contracts`)
- Kontrak schema Zod per-layanan ditambahkan pada `packages/contracts/src/index.ts`:
  - `serviceStatusValueSchema`: `'healthy' | 'degraded' | 'down' | 'unconfigured'`
  - `singleServiceHealthSchema`: status, latencyMs, message, recovery
  - `servicesHealthResponseSchema`: status layanan Firestore, Hermes, Model Router, PDF Renderer, dan WhatsApp beserta panduan pemulihan (`recovery`).
- Endpoint `/health/services` dan `/api/health/services` diimplementasikan di `apps/server/src/modules/health/`.
- UI `apps/web/src/office3d/OfficeSpikeView.tsx` menampilkan badge "DEVELOPMENT LOCALHOST" dengan status indicator interaktif dan modal dialog detail health layanan serta instruksi pemulihan.

### 3. Lifecycle Worker & Graceful Shutdown (`apps/server/src/main.ts` & `app.ts`)
- Handler sinyal `SIGINT` dan `SIGTERM` di `main.ts` memicu `app.close()`.
- Hook `onClose` di Fastify menghentikan calendar scheduler background timer serta membersihkan instance WhatsApp bridge Baileys.

### 4. Skrip Operasional Windows & Backup Harian (`scripts/` & `backup-service.ts`)
- Menyediakan skrip di folder `scripts/`:
  - `start-dev.bat`: Menjalankan server development secara interaktif.
  - `start-dev-hidden.vbs`: Menjalankan server di background Windows tanpa jendela terminal.
  - `install-autostart.bat`: Menaruh shortcut VBS di folder Startup Windows (`shell:startup`).
  - `uninstall-autostart.bat`: Menghapus shortcut dari folder Startup Windows.
- Service backup (`apps/server/src/modules/backup/application/backup-service.ts`) diperluas dengan fungsi:
  - `pruneBackups`: Memangkas backup lama berdasarkan retensi hari (`retentionDays`) dengan batas minimal arsip (`minKeepCount`).
  - `runDailyBackup`: Eksekusi backup otomatis harian yang merangkum Firestore metadata, file privat, dan signature ke folder ber-timestamp ISO yang terverifikasi manifest hash-nya.

## Informasi Rilis & Keterbatasan

### Versi Release
- **Release Version**: `v0.22.0-dev.localhost`
- **Target Platform**: Windows 10/11 x64 (Node.js 24.19.0, pnpm 12.9.1)

### Keterbatasan Aktual (Known Limitations)
1. **Model Router / Hermes CLI**: Di localhost tanpa binary `hermes` terpasang secara global atau credential LLM aktif, status layanan Hermes terdeteksi `unconfigured` atau `down` dan antarmuka beralih ke mode offline snapshot secara aman.
2. **WhatsApp Multi-Device Baileys**: Autentikasi sesi disimpan pada filesystem lokal (`private/whatsapp-auth`). Jika folder sesi dihapus, QR pairing baru harus dipindai ulang via `/whatsapp/pair`.
3. **Headless Chromium**: Rendering invoice PDF bergantung pada Chromium lokal melalui Puppeteer. Ketiadaan executable Chromium di OS lokal akan menandai layanan PDF renderer sebagai `down`.
4. **Cloud Database Dependency**: Database operasional menggunakan Cloud Firestore yang membutuhkan koneksi internet dan file service account `service-account.json`.

### Prosedur Rollback
1. **Aplikasi**:
   - Kembalikan build dengan menjalankan `git checkout HEAD -- apps/ packages/` atau kembalikan versi build sebelumnya dari folder backup.
   - Hentikan proses latar belakang melalui Task Manager (`node.exe` dengan path root `apps/server/dist/main.js`).
2. **Autostart Windows**:
   - Jalankan `scripts\uninstall-autostart.bat` untuk mencabut startup otomatis.
3. **Data & Backup**:
   - Jika terjadi inkonsistensi data, gunakan backup snapshot dari direktori `private/<ownerId>/backups/backup-<timestamp>` dan jalankan fungsi `restoreBackup` untuk memulihkan state metadata Firestore dan file privat.
